CHEMICAL LITERATURE MINING

OVERVIEW

Chemical literature mining extracts structured data — structures, properties,
synthesis routes, and bioactivity — from scientific publications and patent
databases. The goal is to build a curated dataset for a given class of molecules
(e.g., flavonoids, beta-lactams, benzimidazoles).

MAJOR DATABASES

  PubChem (https://pubchem.ncbi.nlm.nih.gov)
    - Free NIH database with 100M+ compounds
    - Bioactivity assay data, structure search
    - REST API for programmatic access

  ChEMBL (https://www.ebi.ac.uk/chembl)
    - Drug-like molecules with bioactivity from published literature
    - Excellent for QSAR (pIC50, Ki, EC50 data)
    - Python client: chembl-webresource-client

  SciFinder / Reaxys (commercial)
    - Most complete reaction and synthesis databases
    - Patent coverage included

  BindingDB (https://www.bindingdb.org)
    - Binding affinities (Ki, IC50, Kd) for protein-ligand pairs

  PubMed + NLP Tools
    - Text mining from full-text papers
    - Tools: ChemDataExtractor, OSCAR4, ChemNLP

  Patent Databases
    - USPTO, EPO, Google Patents


 
MINING WORKFLOW (6 Steps)

  Step 1: Define your chemical class
    Define a core scaffold using IUPAC name, SMARTS, or CAS RN range.
    Example: "all chalcones with antifungal activity"

  Step 2: Substructure / similarity search
    Search PubChem or ChEMBL using SMARTS substructure query.
    Use Tanimoto similarity > 0.6 to 0.8 for analogue retrieval.

  Step 3: Retrieve properties and bioactivity
    Download MW, LogP, TPSA, HBD, HBA, and assay results via API.
    Formats: JSON, CSV, or SDF.

  Step 4: Retrieve synthesis routes
    Collect reaction SMILES (SMIRKS), reagents, conditions, and yields.
    SciFinder and Reaxys are most complete for synthesis data.

  Step 5: Deduplicate and curate
    Standardize with RDKit or ChemAxon Standardizer.
    Remove salts, neutralize charges, deduplicate by InChIKey.

  Step 6: Store in database
    Insert into MySQL or SQLite3 with structure, properties,
    bioactivity, and source DOI or patent number.

SECTION 2: DATABASE CREATION

OVERVIEW

Store your mined dataset in a relational database. SQLite3 is recommended for
beginners (file-based, no server needed). MySQL is suitable for larger,
production-scale datasets shared across teams.

SECTION 3: CHEMICAL STRUCTURE REPRESENTATION


OVERVIEW

Computers represent molecules as text strings or coordinate files.
Each format serves different purposes.

FORMAT COMPARISON


  SMILES (Simplified Molecular Input Line Entry System)
    - Compact linear text notation
    - Best for: databases, ML feature input, data transfer
    - Example: CC(O)Oc1ccccc1C(O)O  (Aspirin)
    - Tools: RDKit, CDK, OpenBabel, MarvinSketch

  MOL / SDF (MDL Molfile / SD File)
    - MOL  single molecule with 2D or 3D atom coordinates and bonds
    - SDF  multiple MOL blocks separated by "$$$$"
    - Best for: exchanging structure sets, visualization
    - Tools: RDKit, OpenBabel, MarvinView

  MOL2 (Tripos SYBYL MOL2)
    - 3D format with explicit atom types, partial charges, bond orders
    - Best for: molecular docking input (AutoDock, Glide, GOLD)
    - Tools: OpenBabel, AmberTools, Schrodinger

  InChI / InChIKey
    - IUPAC standard identifier; InChIKey is a 27-character hash
    - Best for: unique structure identification in databases
    - Example InChIKey: BSYNRYMUTXBXSQ-UHFFFAOYSA-N  (Aspirin)

SMILES SYNTAX RULES

  Symbol      Meaning

  C           aliphatic carbon
  c           aromatic carbon
  N, O, S     heteroatoms (uppercase  aliphatic)
  [NH2]       atom in brackets  explicit hydrogen count
             double bond
  #           triple bond
  ()          branch
  1, 2, ...   ring closure (matching digits)
  @, @@       stereocenters (R/S configuration)
  /  \        E/Z double bond geometry

SECTION 5: MOLECULAR DESCRIPTORS & FINGERPRINTS

OVERVIEW

Descriptors convert molecular structure into numerical vectors for machine
learning. They encode physicochemical, topological, electronic, and 3D
geometric information.

WHY DESCRIPTORS?

ML models cannot read SMILES strings directly. Descriptors are the feature
vectors (rows of numbers) that represent each molecule as input to
scikit-learn models.

DESCRIPTOR TYPES

  Constitutional descriptors (~40)
    - MW, atom counts, ring counts, bond counts, formula weight
    - Tools: RDKit, CDK, PaDEL

  Topological / graph descriptors (~200)
    - Wiener index, Zagreb index, Balaban J, Randic chi indices
    - Encode connectivity without 3D geometry
    - Tools: RDKit, PaDEL, CDK

  Electronic descriptors (~50)
    - LogP, TPSA, pKa, dipole moment, electronegativity
    - Tools: ChemAxon cxcalc, RDKit, Mopac (quantum chemical)

  2D Fingerprints (512-2048 bits each)
    - Morgan/ECFP: circular substructure fingerprints (most popular for ML)
    - MACCS keys: 166 predefined structural keys
    - RDKit FP: path-based topological fingerprint
    - Daylight FP: hashed path fingerprint
    - Tools: RDKit, CDK, OpenBabel

  3D Descriptors (~500+)
    - WHIM, GETAWAY, RDF, MORSE codes
    - Require 3D conformers; encode 3D shape and geometry
    - Tools: PaDEL-Descriptor, Dragon

  PaDEL-Descriptor (all-in-one)
    - Calculates 1875 descriptors (all types above)
    - Free Java tool, also has Python wrapper (padelpy)
    - Download: http://www.yapcwsoft.com/dd/padeldescriptor/

ECFP / MORGAN FINGERPRINT

ECFP (Extended Connectivity Fingerprint):
  - radius2 means ECFP4 (4  2*radius)
  - Each atom is assigned a hash from its local environment
  - Bit is set if that circular substructure exists in the molecule
  - nBits2048 is standard; higher  fewer collisions

TANIMOTO SIMILARITY

Tc  |A intersection B| / |A union B|

  Range: 0.0 (completely different) to 1.0 (identical)
  Threshold guidelines:
    Tc > 0.85  : structurally very similar (scaffold-hopping rare)
    Tc > 0.70  : analogue (same pharmacophore likely)
    Tc > 0.40  : same broad chemical class

SECTION 6: MACHINE LEARNING FOR CHEMICAL DATA

OVERVIEW

With descriptors as features (X) and measured properties as labels (y),
you can train models to predict activity, toxicity, solubility, and more.
This is called QSAR: Quantitative Structure-Activity Relationship modeling.

ML PIPELINE (6 Steps)

  Step 1: Dataset preparation
    - Source: ChEMBL, BindingDB, or your curated database
    - Required columns: SMILES + measured property (pIC50 or active/inactive)
    - Clean: remove duplicates by InChIKey, drop salts, handle missing values
    - Minimum: 50+ molecules for classification; 200+ for reliable regression

  Step 2: Feature calculation
    - Generate descriptor matrix X (shape: n_molecules x n_features)
    - Label vector y  pIC50 values (regression) or 0/1 classes (classification)
    - Rule of thumb: at least 20 molecules per descriptor used in the model

  Step 3: Split and scale
    - Random split: 80% train, 20% test (stratified for classification)
    - Scaffold split: better practice — avoids train/test similarity leakage
    - StandardScaler for continuous descriptors; not needed for binary fingerprints

  Step 4: Feature selection
    - Remove near-zero variance features (VarianceThreshold, threshold0.01)
    - Remove highly correlated features (r > 0.9)
    - Use RandomForest feature importances or SelectKBest

  Step 5: Train and tune
    - Start with Random Forest (robust, handles correlated features well)
    - Tune with GridSearchCV using 5-fold cross-validation
    - Compare: RF, SVM, XGBoost, k-NN, Naive Bayes

  Step 6: Evaluate
    - Classification metrics: ROC-AUC, Matthews Correlation Coefficient (MCC), F1
    - Regression metrics: R-squared (R2), RMSE, MAE
    - Always plot: y_test vs y_pred scatter; confusion matrix; ROC curve

ALGORITHM REFERENCE
Algorithm	Use case           	Key parameters
  Random Forest                       	Both	n_estimators, max_depth, max_features
  SVM (SVC/SVR)                       	Both	C, kernel (rbf/linear), gamma
  XGBoost                           	Both  	learning_rate, max_depth, n_estimators
  k-NN                               	Both	n_neighbors, metric (jaccard for FP)
  Naive Bayes               	Classification	var_smoothing
  MLP (Neural Net)                   	Both	hidden_layer_sizes, alpha, learning_rate
  Gradient Boosting                   	Both	n_estimators, learning_rate, max_depth

EVALUATION METRICS REFERENCE

  Classification:
    ROC-AUC   : area under receiver operating characteristic curve
                0.5  random, 1.0  perfect. Aim for > 0.80
    MCC       : Matthews correlation coefficient. Range -1 to 1.
                Handles imbalanced datasets better than accuracy.
    F1 score  : harmonic mean of precision and recall
    Accuracy  : fraction correct (misleading if classes imbalanced)

  Regression:
    R2        : coefficient of determination. 1.0  perfect fit.
                Aim for R2 > 0.6 on external test set.
    RMSE      : root mean squared error (in same units as y)
    MAE       : mean absolute error (less sensitive to outliers)
    Q2_ext    : R2 on external test set (most important metric)

IMPORTANT NOTES FOR QSAR

  1. Scaffold splitting
     Always prefer scaffold-based train/test split over random split.
     Random split overestimates performance because similar molecules
     end up in both train and test sets.

     from rdkit.Chem.Scaffolds import MurckoScaffold
     # Or use: pip install scikit-mol

  2. y-randomisation test
     Shuffle labels randomly and retrain. If the scrambled model still
     shows good performance, your model is overfitting or the dataset
     has problems.

  3. Applicability domain (AD)
     Only trust predictions for molecules similar to the training set.
     Use leverage (Williams plot) or k-NN distance to flag out-of-AD
     molecules.

  4. Minimum dataset size
     Classification: > 50 per class (better: 200+ per class)
     Regression: > 200 molecules for reliable models

#-----------------------------------------------------------------------------------------
SQL QUERY: Drug-like filter (Lipinski Rule of Five)
#-----------------------------------------------------------------------------------------

 -- Find drug-like molecules active against EGFR with pChEMBL > 7 (IC50 < 100 nM)
 SELECT m.name, m.smiles, p.logP, p.tpsa, p.hbd, p.hba, b.pchembl
 FROM  molecules m
 JOIN  properties p ON m.mol_id p.mol_id
 JOIN  bioactivity b ON m.mol_id b.mol_id
 WHERE p.logP  BETWEEN -0.5 AND 5.0  -- Lipinski: LogP < 5
  AND p.tpsa  < 140          -- good oral absorption
  AND p.hbd  < 5          -- H-bond donors
  AND p.hba  < 10          -- H-bond acceptors
  AND b.target 'EGFR'
  AND b.pchembl > 7.0         -- IC50 < 100 nM
 ORDER BY b.pchembl DESC
 LIMIT 20;
